# Mac area: behaviour notes

Plain-English notes for the files in `Apps/Mac`, `Tools/release`, `Tools/dev` (demo copies) and the mock gateway. The new code was written from these notes, the callers and the tests.

## Shims (iOS spellings on the Mac)
Shared views use iOS-only SwiftUI and UIKit names. The Mac target defines stand-ins: navigation bar and toolbar placements, search drawer, inset-grouped list, paged tab style, tab-bar helpers, text input traits, edit mode, size classes, the numbered system greys and grouped backgrounds as `NSColor`, `UIImage`, `UIPasteboard`, `UIScreen`, `UIGraphicsImageRenderer`. Each is either the nearest Mac equivalent or a no-op. A hidden view fails the build with one clear error if SwiftUI's unavailable declaration ever wins over a stand-in.

## Small helpers
- **MediaSave / MediaFile**: save a chat picture to Downloads without overwriting (Finder-style " 2", " 3"), reveal it, copy it, or drag it out as a file fetched on drop. `failureMessage` is "<name> was not saved to Downloads. <reason>". Tests: MacMediaSaveTests.
- **ContinuityMenuFilter**: removes "Import from iPhone or iPad" items (and stray separators) from context menus that have no Paste. Never touches the menu bar or submenus' parents. Tests: MacContinuityMenuTests.
- **ForceClickMonitor / onForceClick**: a local event monitor turns a second-stage trackpad press into an action on the view under the pointer, once per press; the mouse-up that ends it is swallowed.
- **BotWindowLiveness**: sets `botsLive` from the window being on screen, and for the main window also Nollie being frontmost.
- **MacSleepAway**: marks the runtime away on system sleep and back on wake, nothing else. Tests: MacSleepAwayTests.
- **ReplyCopyHover / TranscriptMedia.copyText**: a copy button beside a reply that shows on hover and for 1.5 s after copying; copy keeps the text exactly. Tests: MacReplyCopyTests.

## Menu bar and app entry
- **TurnBoard / MenuBarTurnReporter**: one list of running turns and waiting approvals, a Dock badge for the ones needing the person, and the bots' ambient flag. `answersInApp` is true for Ask first and sign-in approvals (menu bar may deny, never allow). Tests: AskFirstTests, MacBotAnimationTests.
- **MenuBarIcon**: template image per badge (idle, working, needs you, using Mac), cached.
- **TurnMenu**: rows per turn with approve, deny, answer-in-Nollie, Stop for a Mac-using turn, and a list of bots allowed to use this Mac with Turn off.
- **NollieMacApp**: single window scene, appearance preference, lifecycle (foreground, sleep, wake, lock), the Chat, Go and Board menus, menu bar extra. `MacWindow.openMain` and `bringMainForward` stay.
- **MacAppDelegate**: notification registration and taps, push registration, starts the filter, sleep, sign-ins and (Direct build) the computer, link, live pieces; Dock menu Stop item.

## Window
- **MacRootView**: tour or app, lock on top, window sizing and backdrop, leftover-setup sheet (Direct), `MacPages`. **CompanionOffer**: one-time Companion prompt and installer sheet, waits for tour, lock and sign-in. **MacDemoLaunch** (debug): demo launch flags. **MainSplitView**, **MacSidebarCard/Backdrop**, **MacSidebarFooter**.

## Board
- **MacBoardView**: three lanes, drag between lanes (payload "gateway/board/task"), keyboard (arrows, return, delete, escape), toolbar, status bar, refresh loop (read now, live socket, every 60 s). **MacTaskInspector**: details with in-place edits, runs, log, comments, history. **MacCardMenu**, **MacBoardAsks**, **BoardKeys**, **BoardCommands**.

## Release and dev scripts
- `asc-jwt.swift` prints an ES256 token. `asc-listing.py` attaches builds and replaces screenshots. `feedback-issues.py` files TestFlight reports as issues. `xpost.py` makes the build card and post text. `testflight.sh` archives, checks, exports and uploads. `make-demo-app*.sh` build the demo copies. Tests: `test_release_guard.py`.

## Mock gateway
HTTP routes and the JSON-RPC socket keep exactly the same paths, flags and JSON. Checked by running the old and new servers side by side through every scripted prompt, the RPC methods and the REST routes. Python tests in `Tools/mock-gateway`.

# Second pass (Mac files rewritten again)

## Shims_Controls
Phone-only SwiftUI names that shared views still use, given a Mac meaning. Top-level types, because SwiftUI's nested spellings are unavailable here. Wide size class always; title display mode and the toolbar-visibility call do nothing (the window title names the screen; the Mac toolbar carries the sidebar button); `topBarLeading` and `topBarTrailing` map to the navigation and primary-action placements; `insetGrouped` is the inset list style; `navigationBarDrawer` search is the toolbar field; `listSectionSpacing`, `hidesTabBar`, `tabRoot`, keyboard type and capitalisation hints do nothing. Edit mode, paged tab styles and index styles were dead (nothing reaches them) and are gone, as is the never-shown compile check.

## Shims_Images
The phone's picture names in AppKit: `UIImage`, `UIScreen` (scale and bounds of the main display with fallbacks), `UIGraphicsImageRenderer` (draw into a top-left-origin image; the format's scale is ignored), PNG and JPEG data, `cgImage`, thumbnails that fit a pixel box without enlarging, rendering mode (returns the image as is), `Image(uiImage:)`, and `uiImage` on `ImageRenderer` and Quick Look thumbnails.

## MediaSave and MediaFile
A chat picture leaves Nollie by share sheet (`MediaFile`, fetched from the gateway when shared), by saving to Downloads, revealing in the Finder, copying to the pasteboard, or dragging out as a file fetched on drop. Names are numbered Finder-style ("shot 2.png"; no extension takes the number at the end). Slashes in a name become dashes; an empty name falls back to the source name. A failure reads "<name> was not saved to Downloads. <reason>" and menu actions show it as a sheet on the key window or a plain alert. Share and drag use one fetcher that is nil when no gateway is connected. Tests: MacMediaSaveTests.

## BotWindowLiveness
Sets `botsLive` for a window: on screen (not minimised, covered, another Space) and, for the main window, the window or the app in front. One shared watcher follows app activity for every window. A hidden view reports the window's visibility, handed over a turn later so layout is never mid-pass.

## ContinuityMenuFilter
Removes "Import from iPhone or iPad" entries (and the separators left behind) from context menus that have no Paste. Cleans when a menu starts tracking, again once AppKit has filled it, and on the next turn when such an entry is added to a showing menu. Never touches the menu bar or submenus. Tests: MacContinuityMenuTests. The unused `isContextMenuWithoutPaste` is gone.

## ReplyCopy
`TranscriptMedia.copyText` returns the reply unchanged. `ReplyCopyHover` puts a copy button beside a reply that appears on hover (bubble and button share one hover area) and shows a tick and "Copied" for 1.5 seconds after the latest copy. Tests: MacReplyCopyTests.

## MacBoardInput
`BoardKeys` watches key-downs for the key window: arrows, return, delete and escape, never while a text field or text view has focus and never with command, option or control held. `BoardCommands` carries menu requests (selection, new task, open) to the Board page as fresh ids.

## TurnBoard and MenuBarTurnReporter
`TurnBoard` is the one list of running turns and waiting approvals, with counts, a Dock badge for the ones needing an answer and the bots' ambient "anyone working" flag. `answersInApp` is true for Ask first and sign-in approvals. `MenuBarTurnReporter` (now its own file) keeps a chat's row from the first word until the turn ends; the start time never resets while the row is listed; a deleted reporter removes its row. Waiting lines: "sudo password needed", the approval's words, "Approval needed", "Needs your answer". Tests: AskFirstTests, MacBotAnimationTests.

## TurnMenu
The menu bar drop-down: an idle header when nothing runs, a row per turn (avatar state, name, title, progress words, buttons), then the bots allowed to use this Mac each with Turn off, then the footer ("N need(s) you" or "N working") with Open Nollie. A screen approval offers Allow system control and Keep it off; an Ask first or sign-in approval offers Answer in Nollie and Deny; any other offers Approve once and Deny; a working turn using the computer offers Stop. Rows open a chat by a `nollie://chat/<id>` link naming the owning bot. Buttons are described as a small list and drawn in one loop.

## MacCardMenu
The Board card's right-click menu: Open; Move to (other statuses, the gateway-only ones explained), Reassign and Priority with a tick on the current value; Comment, Unblock or Block, Done, Stop the Worker, Discuss task, by the card's state; Archive and Delete (destructive). Which entries show is decided by a plan value built from the card, separately from drawing. Moves to done, blocked or archived ask first; a refused change shows the store's reason. The ask rule and the confirmed-ask runner are shared with the inspector in `BoardMoves`.

## MacTaskInspector
The chosen card beside the Board: title bar (double-click or pencil to rename, close), then a form of facts (status, bot, priority changeable in place, made, tenant, id), actions (Discuss, Stop), warnings, description (editable), result or latest summary and child results, runs with the worker's log, comments with a box to add one, and history (last sixteen). Re-read when the board is read again and every six seconds while a worker is on the card. The logic lives in `TaskInspectorModel`, the parts in `TaskInspectorSections`.

## ComputerChecks
Behaviour unchanged. The messaging-source list and the repeated "latest messages of a chat" request were rewritten as a built set and one helper.

## ForceClick.swift
A view can ask to be told about a force click (the firmer second stage of a trackpad press) through `onForceClick(perform:)`. SwiftUI never passes pressure events on, so one app-wide local event monitor watches pressure and mouse-up events. Each interested view reports its frame in window coordinates (counted from the top) while it is on screen and withdraws it when it disappears. When a press reaches stage two, the monitor converts the pointer to top-down points in the window's content view and runs the action of the first registered frame that contains it. A press fires once: further stage-two events are ignored until the mouse comes up. That mouse-up is swallowed so the row under the pointer does not also open; every other event passes through. The monitor starts the first time a view registers. Used by the session list on the Mac for its peek.

## MacBoardAsks.swift
`kanbanAsks(ask:answer:notice:answerAsk:)` attaches the Board's question and notice dialogs to a view. When the pending ask wants typed text (a reason or a summary), an alert shows with a text field bound to the answer, a verb button and Cancel. When it is a plain yes, a confirmation dialog shows with the verb (red when destructive) and Cancel. Either way the title and message come from the ask itself. Dismissing clears the ask. A separate alert titled Board shows the notice text with one OK button and clears it. The verb button hands the ask to the caller's async closure. Used by the Board page and the task inspector.

## SleepAway.swift
`MacSleepAway` marks the runtime away when the Mac is about to sleep and back when it wakes, and nothing else (a hidden window or a backgrounded app does not count). It takes a closure that receives true or false. `start(center:)` listens on the workspace notification centre (or one a test passes) and does nothing if already listening; `stop(center:)` removes the listeners; `isObserving` says whether any are in place. `shared` is wired to the current runtime's away flag. Tests: MacSleepAwayTests.

## MacCompanionOffer.swift
`companionOffer(touring:)` is a modifier on the root view. It offers the Companion once per install, after the first gateway connects on this Mac, and it owns three sheets: the gateway sign-in sheet (listing the connections that need signing in), the Companion prompt (install, allow notifications only, or later) and the install wizard in a navigation stack with Done. The sign-in sheet gives way while the lock is on or either of the other two is open. The offer waits while the first-run tour is up, the lock is on, a sign-in prompt is pending or the app still needs a sign-in; it is tried again whenever one of those clears or the gateway changes. Once it decides to offer, it remembers that it asked, then waits up to ten seconds for the gateway's home folder to be known, asks the gateway whether the Companion is installed, and shows the prompt with the version found. If the gateway did not answer in time, or the check failed, it forgets that it asked so the next launch tries again. Choosing install opens the wizard; choosing allow requests notification permission; both mark the notifications card as handled. Later marks nothing.

## MacRootView.swift
The Mac window's root. Before any gateway is saved (or when the debug flag forces it) it shows the first-run tour; after, the split view. The lock covers either with a padlock, "Nollie is locked", the last problem if any, and an Unlock button named for Touch ID or the password; it asks to unlock as soon as it appears. The window's backdrop is clear during the tour and the frosted backdrop otherwise, following the glass setting, strength, reduce-transparency and contrast. The tour sets its own window height through a preference. The view keeps the window-opening action in a static for code with no view (intents), adds the Companion offer and notification navigation, and, in the Direct build, looks once at launch for traces an earlier Nollie left behind (the demo copy can fake one with a flag) and offers the clean-up sheet. Debug builds add the demo launch flags. `MacPages` gives the Go menu its pages (chats, board, schedules) and their menu names ("All Bots" for bots, "Schedules" for cron, otherwise the tab title). `forceWelcome` is a debug-only flag.

## MacSplitView.swift
`MainSplitView(glassPolicy:)` is the app proper: a sidebar of the bot list and a detail that is either the chat navigation or a page. The sidebar is a rounded frosted card with the Board and New Bot buttons in its top right corner (the Board one only when the gateway has the plugin), a fixed width range, and no system sidebar toggle. The detail for chats is a navigation stack of chat routes with no back button, starting from a "Pick a bot" placeholder with the guide character and a hint. Other pages replace the chat, with a back-to-chat button (and a sidebar-show button when the sidebar is hidden) at the leading edge. Bots, schedules (in a stack), board (in a stack) and settings (grouped form) are the pages. The whole view is rebuilt when the page changes. The sidebar's hidden state is mirrored to a shared flag. If the page on show disappears from the available pages, go back to chats. After the connection's profiles arrive, the first visible bot's chat opens once, unless a route is pending, the person has opened something, or the page is not chats; the choice is made again whenever the gateway, profile names, page, path or pending route change. A debug demo flag hides the sidebar after four seconds.

## MacSidebarFooter.swift
The strip at the bottom of the sidebar, 64 points high: the Mac account's initials in a round badge with first name, a spacer, the gateway name with a status dot (green open, orange connecting, red failed or rejected, grey when none) whose help and accessibility text give the connection note, and a gear button that toggles Settings and chats. The gear turns once when the pointer enters (unless motion is reduced), becomes bolder and darker on hover, and carries a red dot while a Companion update is available. Name falls back from the runtime to the saved gateway to "No gateway". The note is the socket's label, or the activation error, or "Connecting…".

## MacAppDelegate.swift
Registers for notification delivery, sets up categories, starts the Continuity filter, sleep tracking and the sign-in centre, and in the Direct build starts the computer features: presenter, start announcements to the phone, the broker when the helper is bundled, the stop-link watcher and live pictures, plus a debug flag that previews a computer card. On quit it stops the computer helper, broker and live hosts. The Dock menu offers "Stop <bot> Using Your Mac" while a task runs. Push registration success and failure go to the model and the cloud alert transport. A remote notification is recorded and its receipt sent. A foreground notification is recorded, its event looked up, and the policy picks how to present it (test pushes allowed). A tapped notification opens the cloud alert, or routes from the payload with the action id and any typed reply; dismiss does nothing.

## NollieMacApp.swift
The app entry. Start-up work: log files, demo mode (debug), legacy folders, keychain access group and its migration, notification preview mirror, and the saved colour scheme applied to AppKit ("light" and "dark" set an appearance, anything else removes the override). One window (id "main") holds the root view with the model in the environment and listens for: scheme changes, URLs, handoff, the app becoming or resigning active, unlock (sign in again if the session expired), and system sleep and wake and screen sleep and wake (lock timing and the bots' ambient flag). On start it activates the saved connection, refreshes cloud alerts and the companion update flag, and in the Direct build updates add-ons in the background. On coming to front it marks the app foreground, refreshes authorisation and alerts, tells the cloud helper which session is canonical, re-reads remembered sign-ins and signs in again if needed. The menu bar extra shows the turn menu with an icon badge: needs you, using the Mac, working or idle. Menus: Settings replaces the app settings item (Command-comma, opens the Settings page); Chat (New Bot, History, Board, Next and Previous Bot, Search, Stop, Approve Once, Deny, Copy Last Reply, each with its shortcut and enabled state); Go (one item per page in the Mac page order, the first nine with number keys); Board (New Task, Open Card, Check for tasks, Refresh Board, only enabled while the Board shows and the plugin is there). `MacWindow` keeps the window id and the open and bring-forward helpers.

## MacBoardView.swift
The Board page. With no gateway, an empty state asks to connect one; with the plugin off, an empty state says how to turn it on; a failed read shows the error; reading shows a spinner. Otherwise three lanes (from the presentation groups) scroll sideways, each at least 292 points wide and filling the width when there is room, with cards. A chosen card gets an accent outline and opens the details panel (360 wide) beside the lanes; choosing a card scrolls its lane to the middle. A bottom bar says live or reading every minute, any error in orange, and when the board was last read. Cards drag between lanes with the payload "gateway/board/task"; dropping onto Blocked or Done asks first (reason or summary), onto the open lane moves straight away; a drop on the lane the card is already in or a foreign payload is refused. The context menu is `MacCardMenu`. The toolbar has a board picker when there is more than one board (with the count needing help in each name and a tick on the current one), an options menu (about the badge, refresh, check for tasks) and New Task. The keyboard moves left and right between non-empty lanes, up and down within a lane, return opens the sheet, delete asks to delete, escape clears the choice, handled by a key monitor that lives only while the page is on screen. A confirmed ask runs the move, comment, archive, delete or stop with the typed text and reports a failure as a notice. Coming back from a card's chat selects it, or says it is gone. The page refreshes when it comes on screen, opens the live socket, and reads every 60 seconds; off screen the socket closes. A setting can ask to land on the Blocked lane. Menu commands (New Task, Open Card) arrive through shared request values. Init accepts a ready store and an initial selection for previews and tests.

## ComputerAppRules.swift
Decides, before a person is asked, what a bot may do with an app on this Mac: use it, only view it, or never touch it with a reason in words. The facts come from the app's own bundle (id, name, category, whether it opens web pages, who signed the copy on disk, where it lives), never from the bot. Checked in this order: no id; Nollie itself (own bundle id, any Nollie id, or the name); System Settings; terminals and coding tools (by id, id prefix, a word of the name, or the developer-tools category); system tools and Finder; password managers (id, prefix or name word); money and crypto apps (finance category, id, or name word); browsers and anything else that opens web pages and is not on the allowed list (view only); then the allowed list, where the copy must be signed by the expected maker (Apple's own apps, or a named team) to be usable, otherwise "not signed by the maker"; anything not listed is not offered. Name words match whole words, or a prefix for words ending in a star. Reading an app from a bundle URL gets its display name, categories and URL schemes, and checks its static signature against the bundle id (Apple, or a team id taken from the signature). A running process can be checked live against the same requirement and the same expected signer. Tests: ComputerRulesTests, ComputerCenterTests.

## ComputerViews.swift
The cards for Nollie Computer. The approval card says which bot wants the Mac, which chat asked (title and platform as Hermes records them), the bot's quoted purpose if any, one capsule per app (with "View only" noted) and per refused app (dimmed, "Not allowed", reason on hover), the line about 30 minutes and risky steps, and Don't Allow and Allow with Touch ID. The confirmation card has a warning hand, the bot's sentence, an optional extra check line, and Stop (red), Don't Allow and Allow Once. The stop panel is a floating glass capsule with the current app's icon, "Using <app>", the bot and minutes left (refreshed every 30 seconds), and a drawn Stop button (never a system style, so it always looks ready). An app icon view shows the app's icon or a "no" symbol. The Beta switch in bot settings turns Nollie Computer on, labelled Beta, and stops any running task when turned off. Tests: ComputerSnapshotTests.

## API notes
`onForceClick` takes its closure unlabelled (`.onForceClick { ... }`); the one caller already used a trailing closure. `MacWindow.openMain` keeps its name and meaning. `kanbanAsks` keeps its labels. Nothing was deleted as dead; `MacAppDelegate.model` moved to an extension.


## Mock gateway, second pass
Same routes, flags and JSON. Inside: sign-in routes are two small tables (controls and the native flow) and a bearer check; schedule routes use one pattern for a job, its trigger, pause and resume; open chats are a `Session` with defaults filled in a loop; lookups of a stored row and of the live chat that owns rows are two helpers; every scripted turn begins its message through one helper; projects, sessions and the socket loop were reshaped without changing an answer. The 111 Python tests pass.

## Demo-copy and release scripts, second pass
`make-demo-app.sh` and `make-demo-app-sim.sh` check the build is a Debug one, copy it, drop the extensions and signing profile, rename it (bundle id `com.coreykozarski.nollie.demo`, name "Nollie Demo"), sign it ad hoc and (iPhone) reinstall it fresh. `testflight.sh` takes the exported product only when exactly one matches, and refuses a build whose log says a delegate method nearly matches its protocol. `xpost.py` draws the title lines from a small table and trims the short post from fixes first, then changes. `feedback-issues.py` builds a crash issue from parts, with the crashed thread when the log is there.
